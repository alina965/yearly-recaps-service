# Yearly Recaps Service

Этот репозиторий содержит файлы проекта, где мой вклад был основным.

## Чем я занималась

Я работала над backend-частью фичи «годовой recap» — логикой, которая собирает активность пользователя за год и превращает её в персонализированный итог для интерфейса.

Из сырых данных (просмотры, поиски, избранное, сделки, объявления, сообщения, сессии) backend формирует готовый результат:

- **роль** пользователя за год (покупатель / продавец / наблюдатель);
- **метрики** — самые релевантные показатели с текстами для карточек;
- **достижения** — ачивки по поведению пользователя;
- **рекомендуемое действие** — одно следующее действие на основе активности;
- **target** для этого действия — данные объявлений (категория, название, цена, фото, статус, просмотры и т.д.).

## Структура backend

Также я прорабатывала и согласовывала структуру backend и контракты взаимодействия между слоями.

```text
HTTP Router (api)
    ↓
Handlers (api/handlers)
    ↓
Service (service)
   ↙              ↘
Engine          Repositories
(engine)        (repository)
                    ↓
                PostgreSQL
```

### Слои и зоны ответственности

- **`cmd/api`** — точка входа приложения;
- **`app`** — запуск и сборка зависимостей (конфиг, логгер, БД, репозитории, сервисы, HTTP);
- **`server`** — HTTP-сервер, таймауты, graceful shutdown;
- **`api`** — роутер, handlers, DTO, middleware;
- **`domain`** — доменные модели (`entity` — сущности БД, `recap` — модели итогов года);
- **`repository`** — агрегация и получение данных из PostgreSQL;
- **`engine`** — правила формирования роли, метрик, ачивок и action;
- **`engine/rules`** — evaluator правил ачивок (`condition`, `all`, `any`);
- **`service`** — координация бизнес-логики (recap, achievements, stats);
- **`catalog`** — встроенные JSON-каталоги текстов (roles, metrics, actions);
- **`config`** — конфигурация через `.env`;
- **`logger`** — структурированное логирование;
- **`postgres`** — подключение к БД;
- **`migrations`** — SQL-схема и seed-данные;
- **`static`** — статические ресурсы (изображения объявлений, ачивок, аватарок).

### Структура каталогов

```text
backend/
├── cmd/api/              Точка входа
├── catalog/              JSON-каталоги ролей, метрик, actions
├── migrations/           SQL-схема и тестовые данные
├── internal/
│   ├── app/              Запуск приложения и сборка зависимостей
│   ├── api/              Роутер, handlers, DTO, middleware
│   ├── config/           Конфигурация окружения
│   ├── domain/
│   │   ├── entity/       Сущности БД (user, listing, deal, ...)
│   │   └── recap/        Модели recap и YearMetrics
│   ├── engine/           Правила формирования recap
│   │   └── rules/        Evaluator правил ачивок
│   ├── logger/           Логгер
│   ├── postgres/         Подключение к PostgreSQL
│   ├── repository/       Работа с БД
│   ├── server/           HTTP-сервер
│   └── service/          Бизнес-логика
└── static/               Статические ресурсы
```

## Что ещё входит в мою работу

- Проработка слоёв backend и разделение ответственности между ними.
- Доменная модель recap (`Recap`, `YearMetrics`) и API-контракты (DTO).
- Генератор recap — сборка итога из роли, метрик, ачивок и action.
- Каталоги текстов для карточек (roles, metrics, actions).
- Синхронизация ачивок перед генерацией recap.
- Миграции и seed для разных пользовательских сценариев.
- Unit-тесты engine и service.
- Docker Compose для локального запуска.
- Structured logging.
